# Research plan: S3 trend-filtered core holding (declared before any run)

Date: 2026-10-24. Author: Claude (designer). Status: **declared**. The strategy, variants and
decision rules below are fixed before any S3 result exists. A change after the first run counts
as a new variant and is reported as such. The owner asked for this line on 2026-10-24 (decision
card "S3 の研究計画を作る") after S1 1.1 failed (`docs/research/2026-10-24-s1-v1.1-results.md`).

## 1. Why a new strategy

S1's two problems were low exposure (about 20% invested) and no edge in its ranking signal
(deflated Sharpe 0.43 with 17 trials). S3 does not rank. It holds a fixed, diversified set of
core ETFs most of the time and steps aside to short Treasuries when an asset's long-term trend
turns down. The aim is a higher invested share and a return closer to the market, with smaller
drawdowns than buy and hold. A 200-day trend filter is a widely documented, simple rule; it is
chosen for robustness, not because it is expected to beat SPY.

Honest expectation, before results: with the owner's 10% drawdown limit, S3 is unlikely to reach
SPY's return (about 13.5% a year with a 34% drawdown on the P2 test windows). Monthly 1–2% stays a
reference only.

## 2. Strategy S3 1.0.0

| Item | Rule |
|---|---|
| Core set | SPY, QQQ, IWM, GLD (four slots, fixed; all in U0) |
| Defensive asset | SHY (in U0), never subject to the trend filter |
| Review | Weekly, at the same review session as S1 (the last session of the week) |
| Trend filter | A core asset is wanted while its adjusted close is above its SMA(`trend_period`) |
| Target | Each wanted core asset at `target_weight` = 25%. Each unwanted slot is held in SHY with the same 25% (SHY target = 25% × unwanted slots) |
| Stops | Every holding has a protective stop at close − `atr_stop_multiple` × ATR(20), as S1, because the risk engine sizes from the stop (STOP-1). After a stop-out the slot is in cash until the next review |
| Exits | A core asset whose close is below its SMA at a review is sold; SHY is reduced or sold when core assets come back |
| Sizing and limits | Unchanged risk engine: risk per trade, 25% position cap, four positions, gross exposure, cash buffer, portfolio volatility, all as configured |
| Data rules | Point-in-time adjusted signals, raw fills, as S1 (TASK-007a) |

Exposure note: with stop-based sizing, a position's weight is at most risk per trade ÷ (stop
distance + 0.5% gap allowance). At 0.5% risk and a 2 × ATR stop (about 2–3% for these ETFs),
each position is about 15–20% of equity, so S3 can invest roughly 60–80%. At 1.0% risk the 25%
cap binds. This is why a second family is declared below.

## 4. Decision rules (fixed now)

A family **passes** only if every rule holds on its chained test windows:

1. CAGR / max drawdown ≥ **0.40** (B0's level).
2. Max drawdown ≤ **10%**.
3. Sharpe (rf = 0) ≥ **0.50**, and deflated Sharpe ≥ **0.80** with N = 25.
4. Positive test return in at least **6 of 9** folds. (Profit factor is reported but is not a
   rule for S3: a holding strategy has few closed trades per fold, so the ratio is not
   meaningful.)
5. Stability: the selected grid point's test return has the same sign as each neighbouring grid
   point's test return in at least **6 of 9** folds (neighbours differ in one parameter step).
   TASK-014 adds the neighbour test returns to the walk-forward output so this rule can be
   evaluated.

Outcomes:

- **No family passes:** S3 stops; S1 1.0.0 stays the paper reference. The report says what the
  results suggest, but no tuning follows without a new declared plan.
- **A family passes:** the passing family with the highest CAGR / max drawdown becomes the S3
  candidate. It runs in PAPER next to S1. The hold-out is opened **once**, only with the owner's
  agreement, and the report states N = 25.
- Even if S3-R1 passes, raising the configured risk per trade for PAPER or LIVE is a separate
  owner decision.

## 5. What the implementation task must add (TASK-014)

- Strategy S3 1.0.0 in `aitrader.strategy` (imports only `aitrader.domain` and
  `aitrader.indicators`), with its own parameters and `params()` identity.
- `aitrader walkforward --strategy S3` with the grid above; the existing
  `--risk-per-trade-pct` and `--prior-variants` options apply.
- Neighbour test returns per fold (rule 5) and the cost share (fees, spread and slippage as a
  share of gross P&L and of the risk budget) in the walk-forward output, for every strategy.
- No change to risk limits, hard caps, configuration files or the execution path.

## 6. Reporting

Sharpe, exposure, cost share, the per-fold table, and the share of months at ≥ 1% and ≥ 2%, next to
B0 (SPY buy and hold) on the same sessions.
